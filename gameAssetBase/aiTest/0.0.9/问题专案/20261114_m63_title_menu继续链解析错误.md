# 问题专案：title_menu 继续链解析错误（m63，2026-11-14）

## 现象
作者启动报错：
```
ERROR: res://addons/thx_gamekit/editor/title_menu.gd:114 - Parse Error: Function "_open_editor_os_window()" not found in base self.
ERROR: gdscript_resource_format.cpp:46 - Failed to load script ... "Parse error".
```
→ title_menu.gd 编译失败 → GameKit 标题灰屏。**这已是同一文件连续第二轮 parse 事故**（m61 重复函数、m62 残留调用）。

## 根因
- m61 独立进程改造：python replace 把 `func _open_editor_os_window` 块替换为 `func _launch_editor_process`，**但 `_on_continue()` 尾部的调用点没跟着改**（残留旧名）。同时那次替换还误匹配出重复 `func _on_menu`（m62 修的就是它）。
- m62 只删了重复声明、验证（EDT_OK）没对最终提交态重跑→坏调用随 d9cc294 入库推送。
- 同一轮（上下文已丢失的 20261114 早间轮）project.godot 被以错误编码写过：中文 `##` 注释变成 mojibake 并被并进一个巨大的引号键里。虽然解析器容忍（引号键合法），但属于必须清的编码烂账。

## 修复（GameKit=9c97f46 / th75=727d4c4）
1. `_on_continue()`：删掉残留调用与无效的标题进程内 `THXKit.load_thx(last)`，改 `_launch_editor_process(last)`——独立进程架构下工程必须在**编辑器进程**内载入。
2. `_launch_editor_process(open_path := "")`：带路径时追加 `-- <路径>` 用户参数。
3. danmaku_editor `_ready()` 尾部：解析 `OS.get_cmdline_user_args()`，发现 .thxp/.thx/.thxe 即 `_load_package()`+工程路径记忆+recent 写入——"继续"按钮闭环：标题读 recent→独立编辑器进程启动即自动载入上次工程。
4. project.godot：乱码行→规范三行（`;` 注释×2 + `renderer/rendering_method="gl_compatibility"`）。**上轮改动意图抢救**：gl_compatibility + vsync_mode=0 = 针对 Optimus 双 GPU Vulkan 同步风暴（每帧 GPU 同步 400ms）的缓解，原样保留只清编码；`max_fps=60`/`main_scene` 完好。若作者要改回 vsync=1 请明示。

## 验证（失误测试五步，全绿）
重复声明扫描（3/1 各就位）→ diff 范围核对（3 文件 +17/-4 恰为本轮意图）→ headless parse（`[标题] _ready 全部完成 +60ms`，零 Parse Error/SCRIPT ERROR）→ 双副本同步（th75 kit pull+standalone 改名复原+零 `##` 残留）→ push（9c97f46 / 727d4c4）。

## 教训
1. **改名必 grep 全部调用点**（双副本）——漏一处=parse 崩，本次事故本体。
2. **验证必须对"将要推送的最终内容"跑；验证与 push 之间零改动**——m62 的 EDT_OK 跑在了错误时点。
3. project.godot 是 mojibake 高危区（Windows 编码+注释语法双重坑）——写它必须走 Read→修改→Write+尺寸断言，注释只用 `;`。
4. 作者令已入记忆（th75-round-close-protocol）：失误测试五步+问题专案存档+可 /clear 提示。
