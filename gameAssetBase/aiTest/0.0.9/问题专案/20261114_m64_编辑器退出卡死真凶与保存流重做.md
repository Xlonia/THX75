# 问题专案：编辑器退出卡死真凶修复 + 保存流重做（m64，2026-11-14）

## 现象
- 独立 Windows 进程架构（标题常驻+编辑器=独立进程）下，**编辑器窗口退出后仍卡死**——架构替换后病灶跟着走，证明根源在退出链代码本身。
- 复盘两天遗留：菜单"导出成品(.thx)"/"导出发布包(.thxe)"点击无反应（死菜单）。

## 根因（代码实锤，非环境）
`danmaku_editor._after_exit(mode)` 旧实现三模式双病根：
1. **"close" = `(get_parent() as Window).queue_free()`**——独立进程里编辑器主场景的 parent=根 Window，queue_free 把窗口销毁但**进程不死**→无窗僵尸进程继续耗 GPU/CPU = 作者"就算是新 Windows 窗口也退出后卡死"的真凶。
2. **"title"/"quit" = `goto_scene(title_menu)`**——编辑器进程内做卸载→挂载场景切换=老空转病根，且凭空多出第二个标题画面。
3. 死菜单根因：菜单 items 数组文字与 handler match 键不一致（"导出成品(.thx)" vs "导出拓展(.thx mod/...)"）——上下文膨胀期敷衍产物；同类：`items.erase("导出为官方数据")` 对从未加入的项做 erase=无效空操作。

## 修复（GameKit=c1cd178 / th75=d5d9ad9）
1. **_after_exit 推翻重写**：`_in_window_mode()`（parent=根 Window=独立进程）→ `get_tree().quit()`——标题进程仍在，用户自然回到标题窗口；嵌入宿主进程的遗留路径→回宿主标题。
2. **保存流重做（作者指定）**：
   - Ctrl+S / 菜单"保存"：已有工程=覆盖保存（零对话框）；新工程=系统资源管理器对话框（native FileDialog）
   - Ctrl+Shift+S / 菜单"另存为(.thxp)"：恒弹系统对话框
   - 退出面板"保存并退出"：新工程=对话框选位置→保存完成后才退出；**对话框取消=留在编辑器**（canceled 处理）
3. **死菜单修正**：items 与 handler 键统一（导出拓展(.thx)/导出发布包(.thxe)）；工程环境正确追加"导出为官方数据"（删除无效 erase）。
4. **复盘清理**：title_menu 撤诊断哨兵自动挂载+分段计时 print（专案结案）；TitleDeco 复位（A/B 实验已证无罪）；`use_native_dialog` 重复行删除。

## 验证（失误测试五步全绿+新增永久探针）
- 残留扫描（零旧调用/死菜单键）→ 重复声明扫描（五函数各一份）→ diff 范围核对 → headless 解析零错 → **exit_probe：编辑器挂根 Window（复刻独立进程位）→`_after_exit("quit")`→godot_exit=0 进程自退**（旧实现下=exit 2/超时，即卡死自动化复现）。
- exit_probe 已入 Tests/GUIDE.md=退出链永久回归守卫。

## 遗留与教训
1. **th75 battle_arena.gd:4160 仍用 goto_scene 进 kit 编辑器场景**（th75 游戏进程内切场景）——修复后该路径退出=quit 整个 th75 进程（旧代码=root Window free=僵尸）。建议下轮改为独立进程启动（同 bat 模式）。
2. 教训：**窗口销毁≠进程退出**——Godot 里关窗的唯一正确姿势=场景树 quit；任何"窗口化"实验必须配 process 级验证（本探针已固化）。
3. 教训：菜单文字与 handler 键是两个独立字符串=漂移高发区；改菜单必须同改 handler。
