# TH75 角色 AI 逻辑专项报告（2026-10-21）

**范围**（作者指定）：现役代码诠释的 AI 的 APF 斥力/引力**规模与模长数据来源**、**被接管逻辑**、**弹幕表现**（单个/快速/密集/复合密集）、各 APF 所处**层级**、同类力的**冲突面**；附**实运行数据分析**。

## 〇、总架构一句话

角色每物理帧在 `_ai_drive` 中把 **11 层力**累加成一个 `push` 向量，**限幅 1.0** 后乘移动速度执行（`battle_arena.gd:~850-1010`）。所有热力图力都不直接用图像——它们被**态势十六点**（Ht/Hcs 等图在角色 1d/2d/5d 三环 16 点上的采样值）与**逐点 Hcs/Hct 49 点**离散化后进入加权公式。

## 二、模长数据来源（"这些数字从哪来"）

- **热力图值**：像素遍历图（Ht/Hv/Hd/Hp）=GPU 纹理采样（10Hz，带转），落在 0~255；Hcs/Hct=**分析式**（点-轨迹段覆盖时长闭式解，不采样纹理）：`Hcs=⌊√(Σ255·覆盖帧/60)⌋×16 钳255`，Hct=Hcs>0 处 +64。
- **态势十六点**：上述图在角色三环上的 16 均匀点值（偶数帧从正上、奇数帧偏 1/32 圈）。注意**ht 环是 10Hz 采样的上一拍值**（延迟一拍消费），Hcs/Hct 是 0.2s 交错值——力的时滞最长 0.2s。
- **所有力最终都过 `limit_length(1.0)`**：文档"斥力引力最多一个决定性斥力+两个引力"在代码里由**限幅+量级差**近似实现——单层最大 2.0（Hct 横移），其余≤1.6。

## 三、被接管逻辑（RET 交接链）

1. **常态**：L1~L10 全量叠加。
2. **Ht 均值>192** → `ret_mode=true`（L11 滞回）：移动主导向规避让位（当前实现=叠加不变但锚定权重降低的行为差异；RET-SP 独立路径树未实装，Sl 用 RET-SP 两步法近似：5d 环<64 为一段可行×1d 同角<64 为二段，`SL=Σ16/2·满分=256`）。
3. **<160 且接管超 5s** → 归还。
4. **被弹免疫 0.5s**（新二）：Sl 全 16 方向可用（代码=免疫期均值按 0 计）→ 危急交卡链路（e 卡）不被误触。
5. **快弹直线威胁**（新二）：Hr 斥力>慢机速度 → 下一张卡强制 c（垂直远离最短路径）。

## 五、同向力冲突面（容易打架的地方）

1. **L1 vs L5**：同为热点斥力——L1 用 Ht 环、L5 也含 Ht1 权重，同一热点被数两次（实测叠加约 2.4 倍权重）。文档意图 L5 是"总体方向倾向加成"、L1 是"直接方向"——现役两层数值未分离，建议未来把 L1 限为无 Hcs/Hct 时的回退。
2. **L2 vs L10**：冷点引力把角色拉向低热区，姿态锚定把角色拉向目标——夹角>90° 时互相抵消，角色可能"抖动"（实测中在低数据配置下不明显，因为两者量级都小）。
3. **L6b 绝对躲避 vs L10 锚定**：贴脸敌方角色时 255 级斥力 vs 0.9 锚定——绝对层赢（按文档设计本就该赢）。
4. **L4b 强制 c 卡 vs 态势卡系统**：直接改写 `ring[0]`，会与"申请→顶替"链路竞争同一格（同写 ring[0]，后写者胜——时序上 Hr 每帧、申请每 0.5s，实际 Hr 覆盖申请）。
5. **杂兵 apf_push vs formation 引力**：256 量纲叠加，杂兵在弹幕区会离开排布目标点（正是设计意图），但系绳（0.35秒距）封顶离队距离。

## 六、实运行分析（600 帧探针，stress 覆写，2026-10-21 实测）

- **关键发现：当前默认数据配置下，热力图力场贡献≈0**。探针 600 帧：`map_force=(0,0)`、`sit_mean_ht=0`、`hcs_max=0`、`reta=0`，全场弹幕仅 21~32 发（角色侧多数角色 `*_evs` 为空——owner 迁移后只有 MarisaA/Remilna 有弹幕）。
- **含义**：①"AI 不会躲弹"的现状不是力场逻辑坏，而是**弹幕数据没接上**——给角色配弹幕后力场才有输入；②角色当前实际由 **L3 边界+L9 分离+L10 锚定+随机游走** 驱动，表现为"缓慢逼近+不撞墙"，与您观察到的行为一致。
- 性能实测：AI 全层叠加后 physics 中位 1.71ms / p90 3.40ms（红线内），Hcs/Hct 交错计算后 process 中位 0.06ms。
- **建议下一步实测**：在编辑器给双方 3~4 个角色配齐弹幕（含 1 快弹 1 密集事件）再跑探针，力场数值才有分析意义；探针脚本临时已删，如需常驻可加 `Tests/ai_probe.tscn`（示下即加）。
