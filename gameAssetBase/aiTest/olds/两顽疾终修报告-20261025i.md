# 两顽疾终修：x_copy 消偿语义 + 插入 Godot3 API 报告（2026-10-25 第九批）

**作者要求**：接下来所有工作仅处理两件事——x_copy/y_copy 表现与 x/y 相同；带参插入失效。均已实证修复。

## 一、x_copy"表现与 x 相同"的真因：我此前的"帧控接管"（跳过系统旋转）是错误实现

**A/B 对照铁证**（同链路同目标，x_copy 版 vs 把 x_copy 换成纯 x 的对照版）：两版逐时点方向几乎一致（18°/16°、43°/39°）——作者所见完全复现。

**机制**：您的设计里 x_copy = R(−a)·(x,y) 是**预补偿**——表达式写在未倾斜系，系统的整体旋转 R(+a) 与之相消，副本才能"透过自己的旋转"瞄准真实目标（这就是"集中/平行"用途）。而我此前让"引用 x_copy 的弹幕跳过系统旋转"——R(−a) 没有被消掉，副本方向=R(−a)·目标方向=镜像扇——**与纯 x 走系统旋转形成的扇是同一组方向（互为镜像）**，所以表现完全相同。

**修复**：移除三处旋转跳过（setup 初态/一般类逐帧/物理类逐帧），恢复系统 R(+a)。实测：x_copy 版副本方向收敛到目标方向（t200 时 5°≈目标 1°，带 wobble 螺旋）——与纯 x 版（系统扇形散开）明确区分。XCOPY 正式测试断言同步改为"消偿收敛"（九副本初始方向=目标角，精确通过）。

## 二、带参插入的真因：Godot 3 的 API `get_selected_item()` 在 4.7 不存在

之前三次"修复"都没碰到它，因为都是**读代码推断**。本轮改用**真实 UI 无头测试**（实例化编辑器场景→打开工具浮窗→选中 gettarget→点击「插入」→断言文本变化）——立即抓到运行期错误：`Invalid call. Nonexistent function 'get_selected_item' in base 'OptionButton'`——点击瞬间 lambda 内部崩溃中止，什么都不插入、也无提示（current_build 已非空所以连"请先单击"都不再出现）。**修复**：改用 4.x 的 `get_item_text(selected)`。

**测试实证**：`Tests/insert_ui_test.tscn` 六断言全过（INSERT_OK）——选中 gettarget、参数框选 hpweapon、点击插入、文本精确追加 `gettarget(hpweapon)`。此测试已固化为常驻回归（今后插入链路再坏会直接报 FAIL）。
