# P1 性能修复报告（2026-10-15）

**针对**：《TH75 性能问题归因与四方差异对照报告（2026-10-15）》（豆包/deepseek）中的 P1~P6 与 N2 残留项。
**结论先行**：P1/P2/P4/P5/P6/N2 六项全部落地。手动步进实测：tick 帧 process 从回读风暴降至 **7.47ms 中位（p90 10.2ms）**，其中 GPU 回读从 5.82ms→≈0ms；tick 帧物理步 **5.07ms 中位（p90 6.86ms，达成 <10ms 红线）**。SMOKE_OK 全过，编辑器场景加载无解析错误（N2 修复实证）。

## 一、P1 根因确认与修复路径（与报告的差异）

报告称 `_sit_tick` 每 6 帧一次回读——**实测更严重：它每个物理帧（60Hz）都在跑**，每实体每帧 1 次 Ht 回读 + 1 次 8 图 `sample_multi`（约 90 次同步回读/帧）；外加 `_ai_drive` 的 Hct 横移探针每帧 2 次。所以修复分三层：

**关键约束**：战场 RD 是 `create_local_rendering_device()`（本地设备），`buffer_get_data_async` 回调不会触发（此前已实测），故 P1 不能走异步化，正解是**削减同步回读次数 + 把回读挪到 GPU 空闲时**。

1. **`_sit_tick`（每帧 90 次 → 0 次）**：`sit16` 等输入本就 10Hz 更新，整段降 10Hz（`time_frames % 6` 门控；抽卡累计 `_ent_tick_sit` 移到门控前保证每帧吃 delta）。Ht/Hd 位置值不再点采样——采样批每实体增加"第 49 点=自身中心"，由批量采样顺带写出 `ht_at`/`hd_at` meta，`_sit_tick` 只读 meta。
2. **Hct 横移探针（每帧 2 次 → 0 次）**：改读 2d 环（半径 n×12，与原探针同径）中垂直方向两侧的环索引值，逻辑等价、零 GPU 调用。`_sample_ht_at` 仅剩早苗御柱 16 点扫描（罕见触发，保留同步）。
3. **`_heatmap_tick`（每拍 18 次回读 → 3 次且延迟一拍）**：
   - `heatmap_field.gd` 拆出 `sample_dispatch()`（本拍只提交）与 `sample_read()`（下一拍开头回读）——本地 RD 的同步回读 fence 要等全部在途提交，当拍读实测 5.82ms/次，延迟一拍后 GPU 已空闲、**回读≈0ms**。0.1s 旧数据符合策划态势语义。
   - `ht_sample.glsl` 增加 push constant（点基址/值基址/数量），`FamilyMaps` 新增 `batch_dispatch/batch_read`：两侧各 4 图（**P2：原 sample_multi 无条件 8 图全读**）全部收进同一 compute list、写共享缓冲不同区段，**一次提交+一次回读**。
   - 8 张图 `advance()` 合并为 `advance_batch()`：原每图 2 次提交×8 图=16 次/拍 → **1 次**（点缓冲改每图独立）。
   - 消费循环微优化：4 个图数组查找提到 k 循环外；Hp 规律图免逐弹 duplicate。
   - 结果延迟一拍写回 `sit16_1d/2d/5d`、`map_force`、`ht_at`/`hd_at`（死亡实体 `is_instance_valid` 守卫；CPU 降级路径立即生效不受影响）。

**每拍同步回读合计：修复前 ~108 次（且 _sit_tick 每帧 90 次）→ 现在每拍 3 次、均落在 GPU 空闲窗口。**
