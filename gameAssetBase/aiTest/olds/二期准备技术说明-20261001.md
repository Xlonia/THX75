## 一、重大发现：GPU 管线在 4.7 下从未工作过（已修复）

排查"弹幕被刷成青蓝色纯色圆"时发现，GPU DDM 路径自①期起一直在**静默降级**：

1. **GLSL 注释非法**：四个计算着色器（含 hermes 写的 ddm_clear/ddm_stamps）用 `##` 作注释——GLSL 中 `#` 是预处理符，导入期编译直接失败（`0:2: '#' : invalid directive`），SPIRV 字节码为空。已全部改为 `//`，四个着色器现均编译出字节码（1124/3124/3588/1840 B）。
2. **Godot 4.7 API 变更**：`compute_pipeline_create` 不再接收 RDShaderSPIRV，需先 `shader_create_from_spirv()` 取 shader RID；`uniform_set_create` 第2参数是 **shader RID** 而非 pipeline RID；compute list 创建期间禁止 `buffer_update`。已按新 API 重写 DdmGpu/HeatmapField。
3. **弹幕纯色圆（MultiMesh UV 丢失）**：原 `_quad_mesh` 用 SurfaceTool+Vector3 顶点，canvas draw_multimesh 路径下 UV 未被采样→整面平涂实例色（demo_ring hue=0.55 恰是青蓝）。改为 2D 规范的 `PackedVector2Array` 顶点+ARRAY_TEX_UV 显式建面。
   ⚠️ 请作者下次带窗口运行时确认弹幕已显示材质纹理（tama0 等）；若仍有问题请截图给我。

## 二、热力图注册与构型（批复核心范围）——新增文件

| 文件 | 内容 |
|---|---|
| `shaders/ht_step.glsl` | Ht 步进：①扩散（正交邻域高点×DIFFUSION=0.5，半径1线性）②衰减（floor(0.8h)，批复回归×0.8）③加热（双方DDM并集白区+64，饱和255）。ping-pong 双 R8 400×400 |
| `shaders/ht_sample.glsl` | 态势十六点采样：每线程读 Ht 一纹素→0~255；采样点由 CPU 预计算（含带转偏移），GPU 不做角度数学 |
| `scripts/danmaku/heatmap_field.gd` | **HeatmapField**：GPU 路径（与 DdmGpu 共享同一 RenderingDevice——RD 资源不能跨设备，同队列 FIFO 保证 Ht 读到当帧 DDM）+ headless CPU 降级（100×100 格，仅加热+衰减）；内置 μs 滑动平均计时（性能检测用） |

battle_arena 集成：`_process` 内 `_render_ddm()` 后 `_heatmap_tick()`（每6物理帧=10Hz）：step→收集存活角色 1d/2d 各16采样点→sample→回读→写入 `BattleEntity.sit16_1d/sit16_2d`（③期 AI 消费位）。

**带转已实现**（作者新灵感）：偶数帧从最上端开始，奇数帧整体偏 1/32 圈（11.25°=十六点间隔一半）。
