## 一、项目是什么、现在到哪一步了

**游戏本体**：类海战自走棋的弹幕决斗游戏。核心玩法 = 双方各 5~6 角色 + 最多 5×5=25 杂兵（上限 33 实体）在 400×400 逻辑画布上互射弹幕，被弹按"结界AP + 三部位HP（武器/僚机/机动）"结算；远期（③期）再叠加热力图 AI、态势卡/战术卡抽卡、心情系统。工程为 **Godot 4.7.2 Forward+**（win32），主场景 `scenes/title_menu.tscn`。

## 二、顶层结构：场景流、Autoload、数据流

```
scenes/title_menu.tscn（主入口，title_menu.gd 代码构建 UI）
 ├─ 剧情模式 → story_placeholder.tscn ┐
 ├─ EX关卡  → ex_placeholder.tscn     ┘ 共用 placeholder_scene.gd（占位）
 ├─ 自定义对战 → versus_menu.tscn（5v5 选人+P点+轮射/齐射）
 │               └→ battle_arena.tscn（arena_mode="versus"）
 └─ 弹幕编辑器 → danmaku_editor.tscn
                 └→ battle_arena.tscn（arena_mode="preview" 试炼场，Esc 返回）

Autoload（project.godot）：
 Dialogic                  —— 对话插件（剧情期用，现在闲置）
 GameGlobals               —— scripts/game_globals.gd（全局单例）
 GawWorkbenchRuntimeProbe  —— AI Workbench 运行时探针（调试 MCP 用）
 ProfilerSaver             —— profilersaver.gd（F5 运行时逐帧性能 CSV）
```

**事件数据流**（弹幕的唯一数值数据源 = CSV）：
```
gameAssetBase/danmaku_event.csv（官方5条demo事件，45列）
        ↘ GameGlobals._load_official() → official_events{}
mods/*.thx（zip）→ mod_events{}（同名覆盖官方）
编辑器工作集 → editor_events[]（仅 preview 模式优先级最高）
查询入口：GameGlobals.get_slot_events(owner, slot)（带缓存 _slot_cache）
FireControl 每 0.1s tick → _gate(rate/pattern与门) → fired 信号
        → battle_arena._on_fire → Bullet.new().setup() 入池
```

**战场每物理帧流水线**（battle_arena._physics_process，8 步）：
```
① _player_input    自机移动 + Shift 全队快机（演示）
② _ai_sides        每2帧一次（嫌疑4修复）：敌AI环绕+我方队形跟随
③ _entity_ticks    实体 tick（免疫/瘫痪倒计时）；杂兵排布每3帧（嫌疑4修复）
④ _fire_ticks      FireControl.process（内部0.1s节拍）+ 每300帧重建火力点
⑤ _bullet_updates  bullet_hash.clear() → 每弹 update（零复制共享ctx，嫌疑1修复）
                   → repeat_tick 补发 → O(1) 入格；>6000 抛最旧
⑥ _resolve_hits    被弹：免疫者直接跳过查询；首个命中即结算不排序（嫌疑2修复）
⑦ _update_phase / _check_end（①期只有"全灭→撤离"简化判定）
⑧ _refresh_hud
渲染（_process，渲染线程）：_render_ddm —— 印章导出→GPU compute（嫌疑3修复：
   移出物理线程）；弹幕本体 = MultiMesh 每材质1个draw call + 激光 draw_line
```

**被弹语义（批复二后）**：空间哈希圆碰撞替代 DDM 白点上升沿——快弹穿透不伤害是**可接受**的（作者明示）；0.5 秒免疫 = 该角色整体不参与所有弹幕查询（不只是单弹幕）；无附加判定、无路径跟踪。

### 4.3 实现与策划/批复有出入的点（**需要你知道或拍板**）
1. **main_y/sub_x/sub_y 未按表达式求值**：批复二#1 你答"当然按表达式求值（虽然多数角色不会写变量）"，但 `FireControl._num_db` 仍按字面数值 `to_float()` 读取（注释写"表达式求值属②期"）。当前 CSV 全是纯数字所以无表现问题，但与批复文字不符——建议在性能休整后顺手补上（一次常量折叠求值，开销可忽略）。
2. **poi 的 x 轴镜像**：文档规定"poi x 正方向=该侧朝向"。僚机已按左右侧镜像（side_dir=±1），但**主机左侧火力点没有镜像**（`acc += pv * facing.x` 对左右两排同向）——按文档主机左侧应朝左。需要确认 MarisaA 的 `(to_c+1)*wpcs` 在左侧的预期表现再改。
3. **wpcs 渐进"收回"动画未真正分级**：代码里 `_poi_wpcs_cursor` 每6帧+1 但从未被读取；实际是每6帧全量重算所有点。表现上少了"逐档收回"，且 cursor 是死变量。
4. **快弹-1伤害可顶替真弹**：`_resolve_hits` 首个命中即 break，若该键是 `-1|n`（预警期激光/慧音假弹幕），`take_hit` 拒绝但不继续找同帧的真伤害键——预警期激光会"遮蔽"同帧普通弹。文档语义是非法伤害不参与被弹结算。一行 `continue` 的修复（不影响性能），等你允许。
5. **编辑器二次预览的缓存陈旧**：`GameGlobals._slot_cache` 在 preview 时缓存了 editor_events 查询结果，返回编辑器改动后再进试炼场可能仍用旧事件（`_on_preview` 没调 `invalidate_caches()`）。
6. **F3 的 GPU 调试显示每10帧 queue_free+重建 Sprite**（调试功能，无碍玩法，仅记录）。
7. **DdmField（CPU 0期遗产）闲置保留**：占 5.7KB 代码但运行时不实例化；是否删除由你定（③期热力图可能参考其接口）。
8. **敌 AI 每2帧 move 未补偿速度**：敌人实际移动速度=标称一半（formation 有 dt×3 补偿，AI 没有）。是修复嫌疑4时的副作用，需确认是否接受。
9. **批复一#14"其它的弹幕均为Godot粒子"**：现用 MultiMesh（非 GPUParticles）——0期起就与你确认过偏差（GPUParticles 无法低成本读位置做 DDM 注册），继续维持 MultiMesh 路线。
10. **profiler 的 script_ms 恒为0**：Performance 无直接监控项，你关心的 Script Functions >100ms 要在编辑器 Profiler 面板看，或后续给 ProfilerSaver 补时间采样。

### 5.2 尚未验证（**接手后第一件事**）

### 5.3 我通读后认为的现存性能注意点（按风险排序，未改动）
1. **`_render_ddm` 每帧 CPU 侧导出印章**：`_process` 里遍历全部弹幕、`PackedFloat32Array.clear()+append`（可能反复扩容）、激光每顶点一枚印章（601点激光×数发即逼近 SSBO 16384 上限）。1000 弹时这是每帧 ~4000 次 append + 2 次 buffer_update。**可改为预分配复用缓冲 + 激光按 laser_n_step 降采样**；也可以在"无人看 F3、无 AI 消费"的对战模式里直接降频（例如每3帧）——需要你拍板，因为 GPU DDM 目前唯一的消费者是 F3 调试。
2. **`draw_bullets` 每帧按材质分桶**：`by_tex` Dictionary 每帧重建 + `set_instance_transform/color` 每弹两次调用。这是 MultiMesh 路线的固有成本，暂时合理；②期可把颜色并进 transform（贴图变体）省一半调用。
3. **`_refresh_hud` 每物理帧拼字符串**：建议降到每6帧（与分频节奏一致），纯赚。
4. **`_spawn_bullet` 里 O(火力点总数) 的 ctx 线性查找**：每次发射遍历所有 fc×points 找 point；repeat 补发多时放大。可用字典或让 FirePoint 直接持有 ctx。
5. **BulletHash insert 对大半径弹**（材质 64px）会写多格；query_keys 固定 +32px 填充对 >32px 半径的弹有漏检可能——目前材质最大 16px 无实际影响，记为护栏。
6. 表达式引擎已做常量折叠+复用缓冲；剩余大头是**逐弹逐帧 x/y/speed 求值**——②期方案（纯 t 一次多项式闭包表）已在 tech_spec2 记录，密度再上去时启用。

### 5.4 性能工作守则（从你三次指令提炼，后续会话同样遵守）
- 每次改动/检查点/收尾都把 physics/process 压回 60 帧（<16.7ms，目标各线程 <10ms）；
- 高频循环（每帧×每弹×每实体）写之前先问"能不能跳/分频/复用"；
- 显著影响帧率又找不到补救的改动 → 自动放弃并写明理由交你分析；
- 测试一律 F5 普通运行调试 + 读报告（ProfilerSaver CSV + 编辑器 Profiler 面板），不以 headless 渲染帧为凭；
- 能跳则跳、能省则省，"这只是个游戏，不是网安"。
