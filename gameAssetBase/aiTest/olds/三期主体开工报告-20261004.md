根因：确认对话框/文件对话框/工具浮窗 `add_child` 进了编辑器 Control 子树——**TabContainer 把控制子节点也当页签**（弹窗关闭后残名占位）。全部改挂**窗口根**（`_dialog_reparent`：get_window().add_child），并在构建期用 call_deferred 防忙挂载。切运行方式→弹窗→确认，不再产生占位标签。

## 七、追记（2026-10-04 晚）：运动方式切换失效排查与修复

作者报告：切换运动方式既不弹确认窗也不切换。排查结论与修复：
- **根因**：弹窗统一挂窗口根的改造引入回归——只 `add_child`（还是延迟的）从未调 `popup_centered()`；Window 默认隐藏 → 确认窗永不出现 → 无法确认切换。同模式波及工具浮窗与查找弹窗。
- **修复**：`_dialog_reparent` 统一收口为"延迟 add_child + 延迟 popup_centered"（同帧 FIFO 保序，add 必先于 popup；构建期/交互期两相宜）。三处调用点全部收口，并删掉了切类型流程里残留的重复 `popup_centered()`。
- **自动化自检**：程序化触发 `_on_tag_switch` → 弹窗入树且 `visible=true`（此前为 0 个）。编辑器/冒烟回归全过。
- **教训入记忆**：Window 类控件 add_child 后必须显式 popup/show；批量脚本改完必须跑解析检查（本轮又拦下两处引号/缩进伤）。


## 八、追记 II（2026-10-04 深夜）：预览/弹幕显示反复操作后提交 11G 死机——排查与修复

**作者症状**：反复更新试炼场预览与弹幕显示后死机；实际占用约 2G，但**提交（commit）高达 11G**。

**根因（特征完全吻合）**：提交=驱动层预留的虚拟内存。战场每次实例化都执行 `RenderingServer.create_local_rendering_device()`——**新建一整个本地 Vulkan 设备**（含驱动堆预留，GB 级提交、低实占），而战场释放时从不释放它。每预览一次泄漏一个设备；十次上下即 11G 提交。次要项：每会话的 DDM/热力图纹理、SSBO、管线、uniform set 等 RID 也全部泄漏（单会话约 MB 级，累计可观）。

**修复（三层）**：
1. **设备单例化**：`GameGlobals.arena_rendering_device()`——本地 RD 一次创建、全局常驻到退出；战场一律取共享句柄。提交量从"每会话 GB 级增长"变为**首次会话后恒定**。
2. **会话级 RID 释放**：`DdmGpu.shutdown()` / `HeatmapField.shutdown()` 逐项 free 本实例的纹理/SSBO/管线/uniform set/shader RID；战场 `NOTIFICATION_PREDELETE` 时先热力图后 DDM 依序释放（热力图 set 引用 DDM 图，先拆引用再删图）。
3. **自检**：连续三轮创建/释放战场——共享设备句柄恒定、全局设备存活、无新增本地设备（脚本化断言通过）。

**边界说明**：游戏刚启动立刻进战场时首次设备创建可能失败（尚无渲染帧）——该会话自动降级为无 GPU 路径，**下一会话重试即成功**（正常流程先进标题页有渲染帧，不受影响）。弹幕显示浮窗本身经查无泄漏（窗口存在时只 `set_event` 覆盖；关闭即释放）。

**验证**：冒烟 SMOKE_OK；战场 600 帧 0 错误（60fps，physics 11.3ms / process 11.9ms）；编辑器带窗口 0 错误。**请作者复测：反复预览×10 次以上，任务管理器提交应稳定不再增长。**

## 十一、追记 V（2026-10-05）：瞬时类性能排查修复 + ③期 AI 收尾

### 1. 瞬时类（激光）性能——你的怀疑属实，三处放大器全修 ✅
代码证据（修复前）：
① **export_stamps 每采样一枚印章**：601 采样的激光=每帧 601 枚印章/发（Nodes 类只有 1 枚）——10 发长激光即 6000 印章逼近 SSBO 上限，SSBO 上传 ~96KB/帧；
② **overlaps_circle 线性扫全部线段**：每个触及该格的实体查询都要跑最多 801 段圆-线段距离（Nodes 是单点圆判定 O(1)）——被弹查询里的百倍差价；
③ 动态重采样 801×2 求值/6帧。
