## 一、HS 上色——这次是真着色器（作者批注"情况依旧"的根治）

前两轮用乘色（modulate）模拟，本质是 RGB 相乘：固定亮度永远参与，达不到"白仍白、灰部上色"。本轮改用**真正的 canvas_item 着色器** `shaders/bullet_tint.gdshader`：

```
L = 纹素亮度(0.299/0.587/0.114) → 输出 = HSL(目标色H, 目标色S, L)
```

即**覆写 H 与 S、亮度逐像素继承纹理**——与 Minecraft 草皮上色/东方原作同构。实例色从 from_hsv(hue, sat, 1) 传入，着色器内还原 H/S。alpha=纹理α×表达式α。弹幕 MultiMesh 独立成层（bullet_mm_layer）挂此材质——draw_line（激光/轨道）不吃该材质所以必须分层。编辑器"参数速览"浮窗同用此着色器，改色相/饱和度立刻可见。**请务必运行确认**——这轮如果还不对，请截一张我方弹幕的特写给我。

## 二、DDM 60帧 + 主设备路线的失败记录（作者批"低级错误"的回应）

批复明确：DDM 是 60 帧渲染的，0.1 秒的是像素遍历图。事实核查：**DDM 的 compute 提交一直是每帧**（_process 每帧 render），10Hz 的只有 F3 调试显示的重建节流——是我此前的注释误导了你，已全部更正并取消显示节流（零拷贝路径每帧换引用）。

**零拷贝尝试与放弃（按性能守则报告）**：为了 Texture2DRD 零拷贝显示改用主渲染设备（RenderingServer.get_rendering_device），实测**帧率掉到个位数**——主 RD 上每帧 compute 提交与渲染线程互相等锁（CPU 几乎空转=纯等锁）。已回退本地 RD（各线程正常），F3 显示保留回读（10Hz，仅调试路径）。放弃理由：调试显示的收益不抵全场帧率损失；本地 RD 的 compute 本身仍是 60 帧提交，符合批复。
