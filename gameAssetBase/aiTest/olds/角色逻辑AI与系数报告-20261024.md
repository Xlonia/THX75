## 一、角色逻辑AI系统（决斗设定-新 L155-170）+ 系数

**结构**（`BattleEntity.ai_logic`）：`{stance: approach/standoff/none, stance_dist, metric: 目标选择器, aim, volley, cruise}` + `ai_target`（选择器命中者，0.5s 刷新）。选择器六比较量：hp_max（主力）/ap_max/hp_any_low（围剿近似=总HP低者优先）/ap_ratio_low（挫其锐气近似）/dist_min/dist_max——标签检索与"特定角色"待印象标签系统。

**系数设计及理由**（作者授权设定；全部为限幅前力度，进入合力后统一 limit 1.0）：

| 逻辑 | 系数 | 理由 |
|---|---|---|
| 近身 approach | 引力 **0.45** | 需压过 RET-C 冷点引力(0.5×内部归一后≈0.35 实效)但不得压过绝对躲避层(1.0 级)；取 0.45 使"想靠近"在无弹时是主导力、有弹时让位于 L5 斥力(≤0.8) |
| 对峙 standoff 过近 | 斥力 **0.60** | **斥>引**（0.60 vs 0.35）：对峙的本质是"不能被近身"，不对称力度保证目标强行贴近时角色宁可吃冷点引力也要拉开——反向对称会导致贴脸拉锯抖动 |
| 对峙 standoff 过远 | 引力 **0.35** | 弱于近身逻辑的 0.45——对峙型角色本就恋战保守；也低于姿态锚定(≤0.9)使撤退/防御卡不被覆盖 |
| 对峙距 0（回避） | 斥力 **0.80** | 回避是生存级意图，仅低于绝对躲避层(1.0)——被追杀时应能压过锚定(0.9)逃命 |
| 无目标 none | 向场心 **0.15** | 文档："相对安全的地方释放弹幕扰乱"——只需微弱倾向，不与任何战术力竞争 |
| 整体层级 | 第二级（第一级合力之上直接加） | 新二订正原文："第一级的APF的力的矢量和再加上的力……这个力比较小"——已按此结构实现，量级(≤0.8)小于第一级决定性分量 |
| 死区带 | 0.8d~1.2d | ±20% 死区防距离环抖（与 RET 滞回 192/160 同思路） |

**攻击逻辑**：`aim=true`（默认）选择器命中者**替换姿态锚定目标**（沿用既有锚定权重 a0.9/c0.2——不引入新系数，攻击意愿仍由态势卡驱动，符合"角色逻辑是最卑微的、被指令覆盖的AI"定位）；`volley` → FireControl salvo 模式；`cruise` → a/c 态强制 cruise_active（攻击时快机）。

## 四、三 bug 修复

1. **gettarget(d) 静默失效**：翻译原把 d 译作 `target_d`，而变量表叫 `d`——表达式含未注册标识符，编译通过但执行恒失败取默认。修复：`d→d` 恒等 + 全参数映射（ap/pp/normal/hpweapon/hpbody/hpmove/**kp/sp 新增**，ctx 快照填充 kp=pp/上限、sp=符卡数）。修复过程中曾误删 `re_gt.compile` 行（gettarget 全灭）——已补回并以 dbg 实测确认（target_x=268 快照正常、frozen_ok=true）。**这就是"数学算式不能正常运转"的总根因之一**。
2. **非旋转 repeat"失效"**：战场链路实测正常（29/59/89 帧出生）；真断点在**弹幕显示浮窗**——预览原本"不繁殖"，repeat 在浮窗里永远只看到载体。修复：浮窗载体携带节拍、子代禁用、旋转事件整扇重放（与战场同语义）。
3. **x_copy/y_copy（编辑器-新 20261024）**：竖直水平系+旋转结果角构成的坐标轴上目标对起点的坐标=目标相对快照按 −rot_angle 旋转——注册变量、ctx 填充；旋转副本据此可实现集中/平行（物理与节点类表达式直接引用）。
